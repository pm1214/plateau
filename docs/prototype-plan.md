# 最小プロトタイプ開発計画

> **1地域・1体験**に絞った、最初の開発計画です。
> 体験の中身は [concept.md](concept.md) で決めます。まだ決まっていない間も進められる作業から始めます。
> 各作業の「完了条件」を満たし、確認方法を実際に実行してから完了とします。

## 前提

| 項目 | 内容 |
| --- | --- |
| 地域 | 東京駅周辺（3次メッシュ `53394611`、約1km四方）を**仮に**使う。変える場合はこの表を更新する |
| 体験 | 未定（[concept.md](concept.md) の候補A〜Cから1つ選ぶ） |
| 作品の形 | 未定（Web か Unity か）。下の表の「Unity」列で、採用前／採用後に分けている |

「Unity」列の意味:

- **採用前**: Unity を使うかどうかに関係なく、今すぐできる作業
- **採用後**: Unity を使うと決め、[unity-setup.md](unity-setup.md) の手順でプロジェクトを作った後の作業

## フェーズ1: データ確認

| # | 作業 | Unity | 完了条件 |
| --- | --- | --- | --- |
| 1-1 | ビューアで対象地域を見て、建物・浸水想定などのレイヤーの有無を確認する | 採用前 | 使うレイヤーと、そのデータ年度・LOD を [data-management.md](data-management.md) の台帳に記入した |
| 1-2 | 対象メッシュの建物を GeoJSON・CSV に変換する | 採用前 | `out/` に GeoJSON と CSV ができ、棟数を台帳に記録した |
| 1-3 | 体験に使う属性の「埋まり具合」を数える（例: 用途が「不明」の割合、浸水深さがある建物の割合） | 採用前 | 属性ごとの件数・割合を concept.md の該当候補に追記した |
| 1-4 | データの利用条件・出典表記を確認する | 採用前 | data-management.md の「出典・利用条件」に、確認できた事実と確認日を書いた。不明点は「未確認」と書いた |

確認方法の例:

```bash
python3 tools/citygml_to_geojson.py --mesh 53394611 -o out/53394611_bldg.geojson --csv out/53394611_bldg.csv
```

## フェーズ2: 最小操作

体験の土台になる「動かせる」部分だけを作ります。見た目は気にしません。

| # | 作業 | Unity | 完了条件 |
| --- | --- | --- | --- |
| 2-1 | 作品の形（Web か Unity か）を決める | 採用前 | concept.md の「決定状況」を更新した |
| 2-2a | （Web の場合）対象地域だけを表示する画面を作る | 採用前 | 対象メッシュの建物が表示され、カメラ操作ができる |

| 2-3 | プレイヤー（またはカメラ）を地上で動かす | 採用前／採用後 | 対象地域の中を、端から端まで移動できる |

## フェーズ3: 作品独自の体験

## 進め方のルール

- 1つの作業ごとに Issue を作る（`.github/ISSUE_TEMPLATE/prototype-task.md`）。
- 完了条件を満たしたかは、実際に確認方法を実行して確かめる。実行していないものは完了にしない。
- 大きな都市データはコミットしない（[data-management.md](data-management.md)）。
